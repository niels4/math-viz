# math-viz — Browser Math Visualization — Project Conventions

A browser math-visualization project: Vite 8 + React 19 + TypeScript 7, custom file-system routing, per-page CSS Module themes/fonts (offline), Canvas 2D for the plane, GSAP for motion. Scaffolded from the viz3d-factory template with `dev/` pages (developer-facing ad-hoc storyboard) — new viz pages go under `src/pages/<area>/`.

## Imports — project vs relative

- **Project-level imports** (styles, fonts, themes, utils, cross-feature code) **must use `#src/`** — e.g. `import styles from "#src/style/themes/mathviz_arctic_ice.module.css"`, `import fontStyles from "#src/style/fonts/work_sans/work_sans.module.css"`, `import "#src/style/global.css"`, `import { foo } from "#src/util/bar.ts"`. This keeps moves cheap and paths stable.
- **Nearby/relative imports** (same dir or sibling, `*.module.css` next to its `.page.tsx`, `*.test.tsx` next to source) **use relative** — e.g. `import style from "./_root.page.module.css"` in `_root.page.tsx`, `import { helper } from "./helper.ts"`.
- Do not use relative `../../style/...` for project-level styles — use `#src/style/...`.

## Architecture: Pages, Views, Data

`.page.tsx` files are the entry points into the app; the URL determines which page runs.

- **Simple pages are self-contained**: everything for the page lives in its `.page.tsx` file, optionally with a sibling `<name>.module.css` (see `_root.page.tsx` + `_root.page.module.css`).
- **As the app grows**, reusable pieces split into **views** (presentational components) and **data components** (fetching/shaping data). The page's job then is to read the URL and its parameters and connect the correct data to the correct views — pages orchestrate, they don't accumulate implementation.
- Don't extract views/data layers prematurely; split when a second consumer exists or the page file stops being scannable.
- Shared settings that affect multiple views live in `src/state/` as Jotai atoms (e.g. `themeAtom` with `atomWithStorage` persistence); pages read with `useAtomValue` and write with `useSetAtom`.

## Routing

File-system based: `scripts/generateRoutes.ts` scans pages, `src/components/router/` renders.

- Any `src/pages/**/*.page.tsx` with a default-exported component becomes a route: `src/pages/dev/theme-demo.page.tsx` → `#dev/theme-demo`.
- `_root.page.tsx` → `""` (index) and `_not_found.page.tsx` → fallback; both only at the pages root.
- Route and directory names: lowercase letters/numbers/dashes, no leading/trailing/double dashes (`isValidRoute`). Anything else fails route generation.
- Hash-based: route is `location.hash` minus `#`; search params follow `?` (`#dev/theme-demo?theme=tron`).
- A route is a page only if `routes` owns it (`Object.hasOwn`): `#constructor` or `#__proto__` would otherwise read `Object.prototype` and crash the render; they show `_not_found`. Look up any key that comes from the URL the same way.
- **After adding/removing/renaming a page**: run `npm run generate`, and add a TOC link in `src/pages/_root.page.tsx`.
- Route state hooks (from `src/components/router/router-hooks.ts`): `useRoute()`, `useSearchParams()`, `useSetSearchParams()` (merge semantics; `null` value deletes a param).

## Visual Verification

No `agent-browser`: every browser check (page render, screenshots, animation frames, DOM reads) goes through a Playwright `.mjs` script in `.local/playwright/` against the session dev-server port.

To actually see a page (or animation) rendered in a browser:

- Playwright + Chromium ship via `@vitest/browser-playwright` (chromium lives in `~/Library/Caches/ms-playwright`). Put a small `.mjs` script in `.local/playwright/` (gitignored, excluded from coverage) so `import { chromium } from "playwright"` resolves against the project's `node_modules`.
- The user develops in Safari, Firefox and Chrome, so check every change the user will see in WebKit, Firefox and Chromium with equal weight (`import { chromium, firefox, webkit } from "playwright"`). A bug can live in one engine only, as text selection during drags did in WebKit.
- Find the dev server port with `ps aux | grep vite` + `lsof -nP -iTCP -sTCP:LISTEN`, matching the process whose cwd is this checkout. Never assume 5173. Navigate to `http://localhost:<port>/#<route>` (hash routing; vite may bind `[::1]` only, where `127.0.0.1` refuses).
- For animation, capture frames a couple seconds apart: `await page.waitForTimeout(2000)` between `page.screenshot()` calls.
- You can view images: `read` on a screenshot PNG shows it to you. After capturing, look at the shot yourself and iterate on the scene (colors, layout, glow) before reporting done — visual review is part of every page task.

- If the Playwright script fails with `browserType.launch: Executable doesn't exist at .../ms-playwright/chromium_headless_shell-NNNN/...`, the `playwright` npm package wants a newer headless shell than the cached one: run `npx playwright install chromium` and retry (`npx playwright install firefox webkit` for the other two engines, which motion and layout checks use as well).

## Live Editing (user workflow)

The user edits in neovim with the `websocket-text-relay` language server (npm global, wired in the user's lazy.nvim config). It streams unsaved buffer text over a websocket to `vite-plugin-websocket-text-relay` (vite.config.ts), which swaps the module in memory and hot-reloads the page: 30-60 updates/sec, no file save. Status UI: http://localhost:38378. This is the user's primary loop for tuning visualizations (tweak a number, see it instantly).

Agent implications:

- The agent writes to disk; the user's live loop works on unsaved buffers. If the user is live-editing a file, disk edits to that same file can collide with their buffer — coordinate before touching it.
- When a dev server runs, agent disk edits hot-reload immediately, so the user sees agent changes live in the browser without any extra step.
- `vite.config.ts` disables `vite-plugin-websocket-text-relay` when `DISABLE_WTR=1` (`process.env.DISABLE_WTR === "1" || "true"`). Agent starts its isolated server as `DISABLE_WTR=1 npm run dev -- --port <free-port> --strictPort` so it only sees disk edits.

## Coexistence (multiple sessions)

The user runs their own long-lived tmux session (`math-viz`) for manual work, and pi0 may drive additional agent sessions (`math-viz-<branch>`) at the same time. This is the normal state, not a conflict.

- **Never assume port 5173.** Each session's dev server picks its own port — pick a free one (`lsof -nP -iTCP:<port> -sTCP:LISTEN`) and run vite with `--strictPort`; the chosen port prints in vite's `Local:` line. If you start a dev server yourself, pick a free port the same way.
- **Agent/user split:** user live-edits via `websocket-text-relay` on their dev server port (unsaved buffers → vite memory, 30–60fps). Agent runs its own vite with `DISABLE_WTR=1` (disk-only) on a free session port and drives Playwright `.mjs` scripts in `.local/playwright/` against `http://localhost:<session-port>/#<route>` (no `agent-browser`, see Visual Verification). Disk edits stay on the agent port, live buffers stay on the user's — no collision.
- **Never kill tmux sessions, dev servers, or processes you did not start.** The user's session is their workspace.
- Work in your own worktree/branch unless the user says otherwise; the user's checkout is often dirty with their in-progress work.

## Visualization Conventions

- New viz work is pages under `src/pages/<area>/` (one page per route): the page's state builds what a view draws (the plane's scene), and GSAP's ticker moves it. Pages orchestrate (see Architecture); split views/data layers only when a second consumer exists.
- **One number rule**: every number a view shows goes through `src/util/format/number.ts`, never `toFixed` or `String(n)` in a view. Values keep fixed decimals so the decimal point holds still while they slide (the user's ruling, 2026-10-06): `formatNumber` (2), `formatStored` (a stored value: 3 when it has a third or a fine drag holds it), `numberParts` and `relation` (readouts: 0.00 with ≈ for tiny values, scientific from 100000). Scale marks and constants in copy keep the short form: `formatMark` (zeros stripped), `formatTick` (axis and scrubber ticks). Values sit right-aligned in tabular figures; a readout keeps slots as wide as the plane's view prints (`panel/readoutFit.ts`).
- **Motion tokens** live in `src/util/motion/motion.ts`: durations (`leave` 120 ms for things going), the sweep and enter springs as GSAP eases over their settle time (`ENTER_SETTLE_MS`, 643 ms: the enter spring at its own pace), the draw-on cubic-bezier, `OVERLAY_LEAVE_MS` (200 ms: the settings menu, the explainer and the tour card going; `overlayLeaveMs()` tells an owner how long to keep one mounted at each motion level), `motionLevel()` (full; reduced: fades of at most 120 ms, nothing travels; none where there is no matchMedia, as in jsdom), and `motionCssVars` for CSS transitions (on the view root, and on any shared part that animates by itself, like `ui/SettingsMenu`).
- **Motion on the plane**: the plane draws what it is told. Scenes carry the motion (`gridAlpha`, a curve's `drawTo` trim along its visible length in `trace.ts`, a point's `alpha`, `labelAlpha`, `labelRise`, `reach`, `tagShift`, handle and guide `alpha`), and an owner animates through `ref.drawFrame(scene | null)`, which holds its frames over the scene prop until null. Hit boxes stay where the marks rest. The plane's own motion is only the edge marker's slide-in (`arrivals.ts`). The Function Viewer's motion is FV 05 as pure functions of time (`motion/fvMotion.ts`), run on GSAP's ticker by `motion/useFvMotion.ts`; the reducer's `change` says whether a change springs (a jump) or follows 1 : 1 (direct). An overlay that animates out stays mounted, inert, through `hooks/usePresence`.
- **Canvas colours**: `useAppTheme().themeVars` resolves every colour token through a probe's computed `color`, so `var()` aliases and `color-mix()` tokens work on canvas. A new canvas colour token goes into `themeColorMapping` in `src/state/useAppTheme.ts`.
- **The Cartesian plane draws scenes**: `src/components/views/CartesianPlane/` takes a generic `PlaneScene` (`scene.ts`) and knows no view's meaning; an owner builds its scene from its state (the Function Viewer's `planeScene.ts`). The plane owns pan, zoom (stops, D17's default by height, keys), grid, chrome and its frame; DOM chrome marked `data-keep-out` pushes tick labels away (an empty part, an owner with no tools, keeps nothing out). It also lays out what the scene's points, handles and annotations draw (`marks.ts`: plates placed clear of the curves and the chrome, point labels placed clear or held in place by `labelPlace`, axis tags, edge markers, hit boxes) before it paints, and tells the owner which draggable point or handle the pointer is over; the owner decides what a drag means (`onMarkDrag`; a handle moves freely, Shift locking one axis). Annotations are lines and filled plates the owner composes (`planeScene.ts` builds k's shift, the unit box, a dragged anchor's tags). The plane answers where its parts are on screen (`ref` → `regionOf(ids)`: curves and points as last drawn, with the axis labels beside them), so an owner can spotlight them; `MiniPlane` draws still illustrations with the plane's painters (the explainers' before and after).
- **P's and Q's labels hold still** (the user's rulings): P's, 2026-10-07: "The p point indicator on the graph is just way too frickin jumpy when it doesn't need to be. its always moving left and right and popping up and down for absoltely no reason. its hard to read the damn thing. i only want it to shift to prevent going off the screen and thats it", because "with some curves, like the sin curve, theres really no good way to avoid the line and instead that logic just makes things worse with all the jumping around"; Q's, 2026-10-08: "fix the q label in the same way. i think its ok for this version if it covers the p label, it looks less janky than always trying to reposition itself as the mouse moves". Each label sits up-right of its point, its left edge 22 px right of the point and its bottom edge 13.2 px above it (`labelPlace: "fixed"`, `placement.ts › placeFixed`), whatever the curve, the transforms or the other marks do. It moves only to stay in view, only as far as that takes: 12 px inside the plane, and off the chrome's plates (out across a plate's thin side, away from the edge it sits on). Where the two meet, Q's label covers P's (Q paints last). Never give either label curve or mark avoidance back: figma0's fvPlace places for P and Q (R2 to R7) are overruled.
- **The x tags hold on the axis** (the user's ruling, 2026-10-08): "now the x axis label also looks janky as it tries to avoid the line, espesially wwith the sin graph". P's and Q's x tags sit centred on the x-axis at their point's x whatever the point does (`placement.ts › xTagBox`), moving only to stay 8 px inside the plane's top and bottom. They used to step 16 px below the axis whenever their point came within 30 px of it, which on sin x is most of the time; now a point on the axis covers its tag's middle. figma0's FV 10 flip is overruled for the x tags. The tick numbers never moved (a tag hides the ones under it); the y tags still step beside the y-axis their point hugs, and a dragged anchor's h tag still goes over the axis rather than under its handle.
- **The plane's view controls** (the user's ruling, 2026-10-07): "the % number between the zoom + and minus is also janky as it keeps changing width. i dont think it adds much at all, please just remove the number display and then put the plus button above the - button, like on google maps. also just above that there should be a return to origin button, again similar to google maps". Screen readers keep the zoom (the spin button's value, an unseen status). The origin button centres the origin and keeps the zoom, as Google Maps' locate button keeps yours; the plane's `0` key still resets both. The owner's tools sit level with the stack's foot, each group its own keep-out, so P's and Q's labels leave the tall stack sideways. figma0's zoom-control-v2 row (− 100 % +) is overruled; the Function Viewer Alpha keeps its own copy of the plane.
- **Callouts**: `ui/Callout` is a card with a caret, fixed to the viewport at a place its owner computes (pure: `panel/explainer.ts`, `tour/tourSteps.ts`); each owner decides what closes it. The explainer and the tour card use it. It comes out of its caret as the settings menu comes out of the gear: from 90 % and 8 px toward what the caret points at, on the enter spring at its own pace, fading in linearly over dur-fast, and back the same way, linearly, in `OVERLAY_LEAVE_MS`; the tour's scrim fades with its card. The 8 px ride in the transform origin (90 % about a point 80 px past the caret), so the card comes from the side its owner places the caret on (see the first-style gotcha). An owner keeps it mounted through its exit with `hooks/useLeaving` and `overlayLeaveMs()` (`closing`: inert), and `glide` springs it between places.
- **Keyboard (FV 07)**: one tab stop per control in reading order (the picker; a, k, b, h by column, each scale's flip toggle before its ruler; Reset all; P's scrubber; the plane; Original; Return to origin; the zoom control); focus looks like hover plus a 3 px `color-mix(in oklch, var(--primary) 32%, transparent)` ring. Both are CSS alone (`FunctionViewer.module.css`) over one DOM, so the plane never remounts on a resize; D17's default zoom (`CartesianPlane/viewport.ts`) follows the plane's height while the view is untouched. The user dropped the Function Viewer's dock on 2026-10-06 as too much motion and commotion: a short window scrolls instead. figma0's FV 06 board is overruled with it (D16, D18's hint under the equation, R9).

## Gotchas

- **GitHub Pages deploy**: `main`'s committed `docs/` is the public site (`https://niels4.github.io/math-viz/`). The build empties `docs/` first, `base: "./"` keeps asset paths relative under `/math-viz/`, and `public/.nojekyll` is copied in so Jekyll doesn't drop files starting with `_`. Lint and format skip `docs/`. The favicon is `public/favicon.svg`, SnowflakeIcon's paths on a tile (`ui/icons.test.tsx` keeps them equal); the build rewrites `index.html`'s `/favicon.svg` to `./favicon.svg`, so it resolves under `/math-viz/`.

- **Router state is module-level singletons** in `router-hooks.ts` (`currentRoute`, `currentSearchParams`). `onHashChange()` runs at import time. Tests leak route state into each other unless reset via `updateLocationHash`.
- `npm test` runs only the jsdom project. The browser project is separate (`test:run:browser`); run both when touching `src/test/` or the router.
- If `npm test` fails, check whether the failure is yours: `git stash -u`, rerun the failing file, `git stash pop`. A failure that reproduces on the clean tree is pre-existing — report it, don't fix unrelated code to chase green.
- `generated/routes.ts` is committed and must be regenerated (`npm run generate`) after page changes, or new pages 404 to `_not_found`.
- `npm run format` (oxfmt --write) formats the whole repo, not just the files you edited: it also reformats markdown tables (including this AGENTS.md) and CSS. Check `git status` after formatting; unrelated files may change.
- **The user's checkout is often dirty with in-progress work.** Before running repo-wide commands like `npm run format`, run `git status` (and `git diff` if needed) to see what the user already has in flight. If formatting would touch files you did not edit, prefer `npx oxfmt --write <your-files>` instead. Never discard working-tree changes with `git checkout --` or similar without asking.
- **zsh does not word-split an unquoted variable**: `npx oxfmt --write $FILES` passes the whole list as one path and oxfmt finds nothing. Pipe the list instead: `git diff --name-only | xargs npx oxfmt --write`.
- jsdom has no `requestAnimationFrame` (it exists only with `pretendToBeVisual: true`). Animated pages must guard their rAF effect with `if (typeof requestAnimationFrame !== "function") return`, or jsdom tests throw.
- **Vite HMR vs `page.reload()` race**: right after a disk edit, `reload` can still serve the old module; identical pixel samples across two edits mean stale content. Read back a DOM attribute (`circle r`, `stroke-width`) via `page.evaluate` to confirm the change landed, or sleep 2s and reload again.
- **Thin strokes at DPR 1 depend on sub-pixel placement**: a 1.5px vertical line centered at x=789.15 renders as one ~100% pixel plus one 65% pixel; widths below ~2px read thinner and darker than intended. Compare pixel rows against the reference, and design with DPR 2 in mind (check `devicePixelRatio` via `page.evaluate`).
- **Figma centres a dash pattern on the path's start**: the first dash runs from half a dash before it. Canvas `lineDashOffset = dash[0] / 2` (SVG `stroke-dashoffset` likewise) puts dashes where the boards do. A dashed curve figma0 built from dense samples renders denser on the boards than its numbers (R3's ghost, dashed 6 6, measures about 6 on and 2 off): build the Specs' numbers.
- **Headless screenshots skew a display-p3 canvas**: they show its raw P3 values as sRGB (sRGB `#0e7c6b` on the plane's P3 canvas shoots as `#387a6c`), while `getImageData` in sRGB and real screens are right. For colour judgements, wrap `HTMLCanvasElement.prototype.getContext` in the screenshot script's init script so it asks for `colorSpace: "srgb"`; the app keeps P3 (the user's choice, `05bf5a2`).
- **Chromium's `line-height: normal` rounds ascent and descent up separately**: 13 px Roboto Mono gets an 18 px line where Figma's AUTO box is 17. Where a box height must match the design, set the line height in px.
- **Canvas pixel probes read coverage from alpha**: the plane's canvas is transparent, so `getImageData` returns a stroke's own RGB at any coverage and the alpha is the coverage; a colour-only match also catches the 0.5 px grid lines. Resolve the token through a probe element, draw it into a `display-p3` canvas for its pixel, and test alpha for full coverage.
- **Component modules export only components** (oxlint `react/only-export-components`, for fast refresh): a `.tsx` component's pure helpers go in a sibling `.ts` (`ui/MathText.tsx` + `ui/mathRuns.ts`).
- **Two more oxlint React rules**: a prop that takes a function returning JSX must be named `render…` (`renderThumb`), or `react/no-unstable-nested-components` reads it as a component defined in render; `react/immutability` rejects `seen.count += 1` on a prop even in a test harness, so record into an array (`seen.edits.push(…)`).
- **JSX text-node splits shift glyph shaping by ~1px**: joining or splitting text nodes (e.g. collapsing a multi-node subtitle into one string) moves antialiased glyph edges even when the rendered words are identical. When refactoring JSX around text, keep node splits as-is or re-verify with pixel-row sampling.
- **Refactoring**: use `tslsp-cli` (skill `.pi/skills/tslsp/`) for any identifier/file move — `npx --no-install @0xdeafcafe/tslsp-cli rename-file OLD NEW --dry-run` then without, `rename --symbol OLD --new-name NEW`. Deterministic import rewrites via `tsgo` `workspace/willRenameFiles`. No manual `grep`/`edit`/`mv` for TS symbols.
- `screen.getByTestId`/`getByText` are typed as `Locator` (from `vitest-browser-react`). To introspect DOM internals in jsdom tests, cast first, e.g. `screen.getByTestId("x") as unknown as SVGSVGElement`, then `querySelector`.
- **`sup`/`sub` lose their raised alignment as flex items**: `vertical-align` does not apply inside flex containers, so a `<sup>` in an `inline-flex` row sits at mid-height. Keep typeset math in plain inline flow (fractions as self-contained `inline-flex` boxes) so superscripts stay raised.
- `noUncheckedIndexedAccess` shapes code: `arr[i]` is `T | undefined` — prefer `?? 0` / explicit `if (v===undefined) return` over `!`; `!` is banned by `no-non-null-assertion`.
- `console.log` calls in `router-hooks.ts` and the test setups are intentional debugging output from early development; remove only if the user asks.
- **tslsp-cli gaps (0.6.0)**: no `tidy` command exists, and `code_action organizeImports --apply` deleted still-used imports, added semicolons, then reported clean diagnostics. Use tslsp for navigation/rename/diagnostics only; use `npx oxlint --fix` + `oxfmt` for import changes, and verify every tslsp edit with `tsc`. User ruling 2026-10-06.
- **CSS module `.d.ts` files are tracked but auto-regenerated** by the dev server plugin (new classes appear without hand-edits). Never hand-write them; if typecheck complains about a missing class, check the CSS first.
- **exactOptionalPropertyTypes vs spread**: spreading a possibly-`undefined` value (e.g. `{...{ helpText }}`) into an optional prop errors — use a conditional spread (`{...(v === undefined ? {} : { v })}`).
- **Pointer-capture drags stick, and select text**: element-level `pointerup` misses releases outside the window or focus loss mid-drag. Pair every capture drag with window `pointerup`/`pointercancel`/`blur` stoppers, `onLostPointerCapture`, and a `buttons === 0` guard in the move handler that stops instead of scrubbing. The plane's pan has them in `CartesianPlane/useZoom.ts` (and the Alpha's copy): a missed release or a lost capture ends the pan without a fling, a focus loss drops every pointer. A release outside the window reaches the capturing canvas in Chromium and WebKit; Firefox sends nothing, so the next move, with no button held, is all the page hears (`.local/playwright/bug-fixes/pan-stuck.mjs`). `user-select: none` on the dragged element isn't enough: WebKit starts a selection inside it and extends it over whatever text the pointer crosses, capture or not. Each drag calls `selectNothingUntilRelease(event)` (`src/util/pointer/selectNothing.ts`) as it takes capture: the document cancels `selectstart` until that pointer lets go (cancelling pointerdown would also stop the focus; a root `user-select: none` lets WebKit's selection appear on release). The dev server serves CSS as written and the build's Lightning CSS adds `-webkit-user-select` for Safari, so WebKit selects on the dev port what it doesn't in the build: write `-webkit-user-select: none` beside `user-select: none`. `.local/playwright/scrub-select-check.mjs` drags every surface in all three engines, on the dev port or a build directory.
- **Lattice loops meet any finite number**: a value field takes 10⁹ or 10³⁰⁰, and a click on P's edge marker pans the plane to P wherever that puts it. A loop that steps `n++` until `n * step` passes a bound never ends once n passes 2^53 (n + 1 is n), and a step list with a last entry puts millions of marks on a huge range (a typed a of 10⁶ drew 406,342 ticks). Grow steps along the open 1-2-5 sequence (`niceStep`) and guard each loop with `Number.isSafeInteger(n)` (`ui/scrubRuler.ts`, `ui/extentTicks.ts`, `CartesianPlane/grid.ts`).
- **Field auto-links labels**: `Field` mints an id via `useId` (explicit `htmlFor` overrides) and shares it through `useFieldId` context (`src/components/ui/useFieldId.ts`); `Select`/`TextField`/`NumberField` consume it via optional `id` props, falling back to their own `useId` standalone. New labeled inputs follow the same pattern instead of taking manual ids.
- The `README.md` is a short public overview; this AGENTS.md is the real documentation.
- **Glyphs the fonts lack**: the vendored woff2 are Google's latin subsets. ≈ renders only through the symbols subsets (STIX, Roboto Mono; `src/style/fonts/README.md` › Symbols subsets), ▲ ▼ ◀ ▶ are `TriangleIcon` (`trianglePath` fills any box, as figma0's triangles do), ← → ↑ ↓ are `ArrowIcon` and key caps `ui/Kbd` (path data in `src/components/ui/glyphPaths.ts`, also for canvas), exponents beyond ³ are raised text. Never type these into Work Sans text. A fallback glyph looks right in a screenshot: confirm the font with CDP `CSS.getPlatformFontsForNode` from a Playwright script.
- **A page without a font module draws the browser's sans-serif**: `#root` sets `font-family: sans-serif` (Helvetica on macOS) and the fonts are per-page modules, so a page or view puts `workSansStyles.font` on its root (the home page, the Function Viewer and the plane do). Helvetica looks plausible in a screenshot: check the computed family, then the face drawn.
- **Which face WebKit and Firefox drew**: CDP's `CSS.getPlatformFontsForNode` is Chromium's alone. In the others, measure the element's text as drawn (a Range over it, with `white-space: nowrap`), then with its family forced to the web font and to `sans-serif`: the width that matches names the face. Load the web font first (`document.fonts.load`): a face no element has used yet is unloaded, and forcing it measures the fallback while it loads.
- **Figma rounds every text box up to whole px** and draws the glyphs at the box's left, so a readout built from runs (`f(` `2` `)` `=` `4`) has up to 0.8 px of air after each run, which a browser's exact advances lose; along a row of runs (a hint, a form line, a tour's words) it adds up to 3 or 4 px. Where the board's spacing shows, give each run that box: `width: calc-size(max-content, round(up, size, 1px))` for any run (`ui/Phrases.module.css`, a fraction's runs in `panel/EquationTokens.module.css`), or `round(up, <its advance in em>, 1px)` where the advance is known. A box in `ch` is exact only in a monospaced face: sage-editorial reads numbers in STIX, whose "." is narrower than a digit, so a run that must hug its neighbour shares a right-aligned slot with it instead (`f(` and x in `panel/PointReadout.module.css`).
- **In the stacked layout the plane sits below the panel**, so a panel part whose height follows the hover moves the plane under the pointer, which changes the hover back. Parts that react to the pointer keep one height at every width (`ui/HintBar` takes three rows' height when narrow, whatever it says).
- **Safari 26.5's container queries misread a zoomed page**: its page zoom (Cmd minus) is the document's zoom, and a size container query unzooms the container only when its `width` is a fixed length. A container of auto width is measured zoomed against the query's unzoomed length: at 85 % section 2's 422 px read 359, fell under `@container (width < 400px)`, and the side layout showed one control per row. WebKit fixed it in 317069@main (July 2026); Playwright's WebKit 26.6 has the fix, so it can't reproduce the bug, CSS `zoom` on the root included. Let a media query inside the layout's own range decide a layout (`panel/TransformGrid.module.css`), not a container query. `ui/HintBar`'s query still fires in the side layout at 75 % or less (72 px tall instead of 48). The user's Safari build (`CFBundleVersion` in `/Applications/Safari.app/Contents/Info.plist`, e.g. 21624.2.5.11.4) has its WebKit source on GitHub at tag `WebKit-7624.2.5.11.4`.
- **Figma's fixed-size frames let content overflow their padding** (R9's section 1 holds 184 px of parts in 182; its 56 px equation row a 57.5 px fraction), where CSS flex shrinks the items instead: give such parts `flex-shrink: 0`, and a fixed height where the board's frame is fixed.
- **Figma counts strokes in auto-layout**: the boards' frames include their 1 px border in layout, so children sit 1 px further in than the padding says (the FV panel's content is 422 wide at x = 35, not 424). A CSS `border` plus the same padding reproduces the snapshot's boxes; so does a dashed ghost slot's outline, which adds 2 px to its term.
- **Discrete properties may transition on every element**: `global.css` sets `transition-behavior: allow-discrete` on `*, *::before, *::after`, because it isn't inherited: on `html`, where the defaults had it (and a typo, `allow-descrete`, dropped it), it reached html alone. So a transition that names `display`, `overlay` or `all` runs them too: `display: none` arrives at the end of the transition instead of at once. No transition in the app names one today; name a transition's properties, as the overlays do.
- **Rules in one layer tie on load order**: two one-class rules in `@layer components` from different modules resolve by stylesheet order, which follows the import graph, and oxfmt sorts imports, so the order can't be steered: `Select.module.css`'s `padding-right` lost to `TextField.module.css`'s `padding` shorthand, which loads after it, and a long option ran under the chevron. A class that must beat a shared base class on the same element needs more specificity (`.select_wrap > .select`), not a later import.
- **`global.css` element rules beat ui components**: it is unlayered, so its `text-wrap` on `p` and `h1`–`h6` overrides a `white-space: nowrap` inside `@layer components` (both set `text-wrap-mode`), and its `input, button { font: inherit }` overrides any font a layered component sets on its input or button. Put the nowrap on an inner span (`ui/TopBar.tsx`) and the font on a wrapper the control inherits from (`display: contents`, `ui/NumberField.tsx`).
- **Chromium sends no pointerout from an input whose text changed under the pointer** (a typed "-2" printed back as "−2"), so React's `onPointerLeave` never fires and a hover state sticks. Use `hooks/useHover.ts`, which also ends the hover on any pointerover outside the element.
- **jsdom's patched `click()`** (`src/test/jsdom-setup.ts`) reads the clicked element's React fiber after the click and throws an unhandled rejection when the click unmounted it (a menu item that closes its menu). Dispatch `new MouseEvent("click", { bubbles: true })` on such elements instead.
- **`npx tsc --noEmit -p .` checks nothing here**: the root tsconfig is a solution file with references. Typecheck with `npm run typecheck` (`tsc -b`).
- **`act` from `#test` doesn't wait for an async callback**: React's act thenable returns nothing from `then`, so `await act(async () => …)` resolves at once. For timers, fake them after the render (`vi.useFakeTimers({ toFake: ["setTimeout", "clearTimeout"] })`), step them inside a sync `act`, and `vi.useRealTimers()` in `afterEach`.
- **Tests that fix a size through `getBoundingClientRect` also stub `ResizeObserver`** (`vi.stubGlobal("ResizeObserver", undefined)`, `vi.unstubAllGlobals()` after): in the browser project the real observer reports the laid-out size over the mock, and pointer maths fail now and then.
- **A `visibility: hidden` element can't take the focus**: a dialog rendered hidden until it is measured silently loses a `focus()` made as it mounts. Keep it focusable while unplaced (`opacity: 0`, `tour/Tour.module.css`).
- **StrictMode runs effects twice in dev**: an effect that moves the focus "as something opens" must remember what it did (a ref) so the second run doesn't act as the next step (`tour/Tour.tsx`).
- **`atomWithStorage` values live in Jotai's default store across tests**: set them in `beforeEach` with `getDefaultStore().set(…)` (the Function Viewer's tests mark the tour done; its tour tests unset it).
- **Motion in tests**: jsdom has no matchMedia, so `motionLevel()` is none and tests see end states. The browser project has one, so the Function Viewer's tests stub it away (`vi.stubGlobal("matchMedia", undefined)`); a test that wants motion stubs a whole MediaQueryList (`useDevicePixelRatio` calls its `addEventListener`).
- **Playwright frames of motion** (`.local/playwright/m11-motion.mjs`): `page.clock.install()` then `pauseAt()` before `goto` fakes `performance.now` and rAF, so GSAP and the canvas step only on `page.clock.runFor(ms)`. On a paused clock Playwright's visibility and actionability waits hang (they wait for frames): poll with `page.evaluate`, click with `page.mouse`. CSS transitions run on the compositor's clock instead: seek them with `el.getAnimations()` (`pause()`, set `currentTime`). Seeked or paused frames give a motion's values at each moment, not whether a person sees it move: judge motion at real speed too, with real clicks and keys on the page's own clock, values sampled every frame with `requestAnimationFrame` and a real-time video (`recordVideo`, in Chromium, WebKit and Firefox; `.local/playwright/menu-motion.mjs`). Under about 100 ms a change reads as instant: M11's settings menu looked right in seeked frames and was 90 % opaque 80 ms after it showed, after 4 px of travel, so people saw it appear.
- **jsdom has no `inert` property**: test `hasAttribute("inert")`, which React sets, not `el.inert`.
- **Firefox paints an opacity eased past 1 washed out**: an easing that overshoots (the enter spring's `linear()`) drives opacity above 1; computed style clamps it, but Firefox (Playwright's 155, filmed at real speed) draws the element faint and bleached until the overshoot ends (the settings menu and the callouts before their real-speed fixes, for about 160 ms after they opened: a card's mean luma per video frame rose 13 to 19 over its rest, which `.local/playwright/callout-luma-check.mjs` flags). Fade opacity on a curve that stays within 0 to 1 (linear over dur-fast) and keep the spring for the transform; the other engines draw both right.
- **A transition starts from an element's first style**: `@starting-style` (and any transition) takes its start values when the element first gets a computed style, and a layout effect that measures it (`offsetHeight`, `getBoundingClientRect`) computes that style before the owner's next render places it. A start value that depends on what that render sets (a callout's caret side) comes from the unplaced state: an explainer placed above its chip slid in from the left under its downward caret. Keep the start value independent of it and put the varying part where it applies live, as `ui/Callout.module.css` puts the travel in `transform-origin`.
- **Filming a CSS transition from its first frame** (`.local/playwright/m12-overlays.mjs`): arm a MutationObserver before the trigger that pauses `el.getAnimations()` as the element appears (from an init script when it appears during load), then seek `currentTime`. After a `waitForSelector` the transition may be over, and a finished one leaves `getAnimations()`. A presence timer runs in real time, so a slow seek outlives the element.
- **A burst of events reads a live value, not the render's**: events that land before React renders again (wheel notches a trackpad sends within one frame, a pinch's moves for two fingers) all see one render, so a handler that computes the next value from the render's counts only the last of them (three notches in one task zoomed one notch). Read and advance `hooks/useLiveValue` instead (synced from each commit), as the plane's wheel and pinch (`useZoom`) and the ruler's wheel (`ScrubStrip`) do; name what it returns `…Ref`, or oxlint's `react/immutability` rejects the handler's write to `.current`. Keys and clicks are discrete: React renders between them. Playwright's `mouse.wheel` waits out a render between notches, so reproduce a burst with `dispatchEvent` in one task (`.local/playwright/bug-fixes/wheel-burst.mjs`).
- **Derived state from a value built in the same render loops forever**: `setState` during render (the "previous value" pattern) compares by identity, so an object literal made in that render never settles. Pass primitives (`useLeaving` takes the explainer's parameter and the tour's step).
- **Playwright same-URL goto**: `page.goto` to the URL the page is on (same hash) is a same-document navigation, so init scripts don't rerun and a localStorage theme change doesn't apply. Set localStorage with `page.evaluate`, then `page.reload()`.
